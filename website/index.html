01 / The pipeline

Context is an input.
Trust is a process.

Small context windows leave little room for noise. Every source passes through six stages before it can reach your model.

01 — INGEST

Keep the source.

Bring URLs, topics, PDFs and Markdown together. Preserve provenance as documents become chunks.

02 — SANITISE

Separate signal from risk.

Redact PII and secrets. Quarantine suspected prompt injections with a report, rather than silently dropping them.

03 — BUDGET

Know what fits.

Use the GGUF model profile and device RAM to calculate a conservative context and KV-cache budget.

04 — COMPOSE

Make every token count.

Stuff, compress or retrieve with BM25. Keep the citations attached and the pack within budget.

05 — AUDIT

Leave a paper trail.

Inspect the scorecard and safety reports. Generate narrow local FastMCP tools, with optional Scorton checks.

06 — REVIEW

A human gets the last word.

Approve locally or through Notion. Export rechecks approval and the content hash before releasing a pack.

APPROVED + HASH MATCH → EXPORTPENDING / REJECTED / CHANGED → REFUSED
02 / Capabilities

Less guesswork.
More control over the input.

⌘

Model & device-aware budgets

Read exact GGUF headers from Hugging Face without downloading weights. Account for layers, KV heads, quantisation and available memory.

⊘

Local heuristic safety

Rules process private data and suspicious instructions before composition. Quarantine reports make the decisions inspectable.

↳

Citations that stay attached

Source provenance survives stuffing, compression and BM25 retrieval, so the resulting context remains traceable.

{ }

Narrow FastMCP tools

Generate standalone, local tools for each pack. Give an agent the capability it needs without an unnecessarily broad interface.

✓

Hash-checked review gates

Drafts start as Pending in Notion or a local registry. Approval is checked again on every export, along with the content hash.

>_

CLI when you want it. UI when you need it.

A Typer CLI for scripts and CI; a Gradio app for Sources → Target → Audit → Export. External services are optional.

03 / Quickstart

Your files.
Your hardware.
Your context.

Run the compiler locally with no credentials for the core offline workflow. Add ingestion, the web UI and services only when needed.

Read the repository docs ↗
# clone and install
git clone https://github.com/NANInithin/AgentMilieu
cd AgentMilieu
python -m venv .venv && source .venv/bin/activate
pip install -e '.[dev,app,services]'
cp .env.example .env   # optional
python app.py          # http://localhost:7860
# see what fits on the device
milieu budget --model Llama-3.2-1B --device phone-6gb

# compile a pack from local files, offline
milieu build --file examples \
  --preset Llama-3.2-1B --device-preset phone-6gb \
  --purpose 'What works offline?' --offline
milieu status PACK_ID
milieu export PACK_ID --out exports  # refused: Pending review
milieu approve PACK_ID               # after reading the draft
milieu export PACK_ID --out exports  # ✓ pack + hashes
milieu reject PACK_ID                # future exports refused

05 / Trust boundaries

Safety-processed.
Not safety by assumption.

Heuristic checks and a review gate are useful layers, not a substitute for production security.

Built into the workflow

  • Compiler drafts and optional service calls use safety-processed data.
  • Every export checks approval status and the content hash.
  • Per-session registries keep pack state separate.
  • Audit previews render as plain text, not untrusted Markdown.
  • Offline mode rejects remote sources and external services.

Before a production deployment

  • Add authentication. Local approval is a demo workflow, not an authorization boundary.
  • Restrict network egress. URL ingestion is not SSRF-hardened.
  • Set upload quotas and a retention policy for persistent drafts.
  • Deploy privately before processing sensitive documents.

Better context starts before the prompt.
